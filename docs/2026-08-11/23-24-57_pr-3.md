# Automatización de Documentación Técnica con Gemini CLI

## Resumen
Se ha implementado un nuevo flujo de trabajo automatizado en GitHub Actions para generar documentación técnica de forma automática cada vez que se realiza un merge de la rama `develop` a `main`. Este workflow utiliza la API de Gemini para analizar los commits y el diff del Pull Request integrado, generando un archivo Markdown detallado en la carpeta `docs/` y actualizando el índice correspondiente. Con esto se asegura que la documentación del proyecto se mantenga al día con cada despliegue a producción sin requerir intervención manual.

## Detalle técnico

### Integración Continua (CI/CD)
- **Creación de `.github/workflows/generate-docs.yml`**:
  - **Disparador del flujo**: El workflow se activa cuando un Pull Request con destino a `main` se cierra. Cuenta con una condición estricta para ejecutarse únicamente si el PR fue fusionado (`merged == true`) y si procedía de la rama `develop`.
  - **Permisos**: Se otorga el permiso `contents: write` para que el proceso de CI pueda realizar commits y push de los archivos de documentación generados hacia la rama `main`.
  - **Extracción de metadatos y cambios**: Realiza un checkout de la rama de destino y extrae mediante Git tanto la lista de commits del rango modificado como el diff de los archivos. Se excluyen del diff la carpeta `docs/` y los archivos de bloqueo de dependencias habituales (`*.lock`, `bun.lockb`, etc.) para reducir el ruido en el análisis. El diff resultante se limita a los primeros 60,000 caracteres.
  - **Generación mediante IA**: Invoca la acción de GitHub `google-github-actions/run-gemini-cli@v0.1.22` con la variable de entorno `GEMINI_CLI_TRUST_WORKSPACE: "true"` activa para habilitar la ejecución confiable dentro del runner. Se le proporciona un prompt estructurado en español con reglas estrictas de formato.
  - **Estructura de almacenamiento**: Escribe el resultado en la ruta estructurada `docs/YYYY-MM-DD/HH-MM-SS_pr-<PR_NUMBER>.md`.
  - **Mantenimiento del índice**: Si no existe el índice `docs/README.md`, lo crea con un encabezado de tabla. Posteriormente, añade de forma incremental un registro por cada PR documentado que enlaza directamente al archivo específico generado.
  - **Commit automático**: Configura un bot de git (`poketeams-docs-bot`) para añadir y confirmar los cambios en la carpeta `docs/`, realizando el push directamente a la rama `main` utilizando `[skip ci]` para evitar bucles infinitos en la ejecución de workflows.

## Cambios de API o dependencias
- **Dependencias de flujos de trabajo (Actions)**:
  - Se introduce el uso de la acción de GitHub `google-github-actions/run-gemini-cli@v0.1.22`.
- **APIs y dependencias del proyecto**:
  - No se identifican cambios en los schemas de GraphQL, dependencias de la aplicación en `package.json` o contratos de servicios REST en este cambio.
